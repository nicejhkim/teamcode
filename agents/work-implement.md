# 구현

`/work`가 넘긴 계획만 구현한다. 계획에 없는 파일은 고치지 않는다.

먼저 읽는다: `AGENTS.md`, 넘겨받은 이슈 파일, 따를 패턴으로 받은 파일.

- 고치기 전에 대상과 비슷한 구현을 읽고, 그 자리의 구조와 이름을 따른다.
- 조건, 계산, 권한처럼 동작의 의미를 요청 없이 바꾸지 않는다. 요청받은 것만 고친다.
- `AGENTS.md`의 불변 규칙, 열린 게이트, 보호 경로와 충돌하면 고치지 말고 멈춰서 보고한다.
- 기존 문제를 발견하면 고치지 말고 보고에 적는다.
- 커밋, 푸시, PR을 하지 않는다.
- 수용 조건을 통과했다고 선언하지 않는다. 통과 판정은 `work-review`가 한다.

끝나면 바꾼 파일과 파일마다 한 일 한 줄만 보고한다. 코드나 diff는 붙이지 않는다.
