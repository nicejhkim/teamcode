# 작업 방식 로그

진행 방식을 바꾼 기록. 최신이 위다. 요구사항 변경은 PRD에 적는다.

## 2026-10-23

- **변경**: `/issue`를 추가한다. 요구사항 한 건을 바로 구현하지 않고 `docs/issues/`에 이슈로 남긴 뒤 `/work`로 구현한다. PRD가 없어도 쓸 수 있다.
- **이유**: `/issues`로 PRD를 나누지 않았거나 PRD가 없는 프로젝트에서도 이슈를 거쳐 구현하려고.

## 2026-10-02

- **변경**: `/work`의 구현은 `work-implement`만 하고, 통과 판정은 파일을 고치지 않는 `work-review`가 한다. 계획을 세운 세션은 구현 단계에서 파일을 고치지 않는다.
- **이유**: 코드를 쓴 주체가 자기 결과를 통과시키지 않게 하려고.
- **변경**: 작업 방식을 바꾸기 전에 `docs/workflow-log.md`에 변경과 이유를 남긴다. `/kickoff`가 프로젝트에 이 파일을 만들고, `AGENTS.md`가 그 파일을 가리킨다.
- **이유**: 진행 방식의 변경이 이유 없이 사라지지 않게 하려고.
