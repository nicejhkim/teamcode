# /issue — 요구사항 한 건을 이슈로

요구사항 한 건을 `/work`가 읽는 이슈 파일로 만든다. 구현하지 않는다. 파일 경로와 코드는 적지 않는다. 어디를 고칠지는 `/work`의 GROUND가 정한다.

PRD를 나누는 일은 `/issues`가 한다. 이 스킬은 PRD가 없어도 된다.

## 0단계 — 입력

사용자에게 묻기 전에 읽는다.

- 인자 문장을 요구사항으로 쓴다. 인자가 없으면 무엇을 이슈로 남길지 한 가지만 묻는다.
- `docs/PRD.md` 또는 루트 `PRD.md`, 그리고 `AGENTS.md`가 있으면 읽는다. 없으면 없는 대로 진행한다.
  - PRD의 범위 밖이거나 불변 규칙과 충돌하면 이슈를 만들지 않는다. PRD를 먼저 고쳐야 한다고 알린다.
  - 열린 게이트에 막히면 이슈는 만들되 상태를 **착수 불가**로 한다.
- `docs/issues/`가 있으면 목록을 읽는다. 같은 일을 하는 이슈가 이미 있으면 새로 만들지 않고 그 파일을 알린다.

## 1단계 — 초안

쓰기에 앞서 초안을 보여 주고 확인받는다.

한 이슈는 끝까지 한 줄로 동작하는 일 하나다. 요구사항에 동작이 여러 개 들어 있으면 이슈 여러 개로 나눈 초안을 보여 주고, 선행을 정한다.

| 항목 | 내용 |
|---|---|
| 제목 | 짧게 |
| 종류 | 사람 결정이 필요하면 HITL, 아니면 AFK. AFK를 우선한다 |
| 선행 | 먼저 끝나야 하는 기존 이슈 번호. 없으면 없음 |
| 스토리 | PRD 스토리가 있으면 그것. 없으면 요청 문장을 그대로 |
| 수용 조건 | 측정 가능한 조건. PRD 성공 기준이 있으면 거기서 가져온다 |

수용 조건을 요청에서 읽을 수 없으면 제안하되 제안이라고 표시한다. 지어낸 조건을 확정처럼 쓰지 않는다.

> 이 초안으로 이슈를 만들까요?

고칠 말이 있으면 고친 뒤 다시 보여 준다. 동의한 뒤에만 2단계로 간다.

## 2단계 — 기록

동의 전에는 파일을 만들지 않는다.

번호는 `docs/issues/`에 있는 가장 큰 번호 다음이다. 폴더가 없으면 만들고 `001`부터 시작한다. `docs/issues/NNN-제목.md`에 `/issues`와 같은 형식으로 쓴다.

```markdown
# 제목

상태: 착수 가능 | 착수 불가
종류: AFK | HITL
선행: 없음 | 001

## 무엇을

끝까지 한 줄로 동작하는 일. 층별 구현은 적지 않는다.

## 스토리

- PRD 스토리 또는 요청 문장

## 수용 조건

- [ ] 측정 가능한 조건

## 막힌 이유

착수 불가일 때만. 게이트와 확인할 대상.
```

이슈 트래커 설명이 `docs/agents/issue-tracker.md`에 있으면 그 방식을 따른다. 없고 `gh`로 이 저장소에 이슈를 만들 수 있으면 한 가지만 묻는다. 추천은 `docs/issues/`만 쓰는 것이다. `/work`가 그 파일을 바로 읽기 때문이다.

> 이슈를 GitHub에도 등록할까요?

등록한다면 파일과 같은 본문으로 만들고, 만든 번호를 파일에 적는다. 기존 이슈는 수정하거나 닫지 않는다.

## 3단계 — 안내

만든 파일 경로를 알리고, `/work docs/issues/NNN-제목.md`로 구현할 수 있다고 알린다. 착수 불가면 게이트가 닫히기 전에는 `/work`로 시작하지 말라고 알린다.
