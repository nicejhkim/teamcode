# /kickoff — 인터뷰 → PRD → 하니스

새 프로젝트를 **"무엇을 만들지"가 합의된 상태**로 만들고, 그 합의가 구현 중에 무너지지 않도록
최소한의 하니스(AGENTS.md 불변 규칙 + 보호 경로 가드)를 깐다.

산출물 4개:

| 파일 | 내용 |
|---|---|
| `docs/PRD.md` | 인터뷰 결과 PRD ([prd-template.md](prd-template.md) 형식) |
| `AGENTS.md` | 프로젝트 요약 + 불변 규칙 + 열린 게이트 (짧게). Cursor·Codex 등 다른 AI 도구도 읽는 본문 |
| `CLAUDE.md` | `@AGENTS.md` 한 줄 — Claude Code가 같은 본문을 읽게 하는 포인터 |
| `.claude/protected-paths` | 보호 대상 설명 (커밋) |
| `.claude/protected-paths.local` | 각자 머신의 실제 보호 경로 (커밋 안 함, 사용자가 직접 채움) |
| `.claude/hooks/protect-paths.py` + `.claude/settings.json` | 위 목록을 강제하는 훅. 저장소에 커밋되므로 플러그인 없는 팀원·Cursor에서도 동작 |

---

## 0단계 — 상태 확인

먼저 파일을 읽어 판단한다. 사용자에게 묻지 않는다.

- 인자로 PRD 경로가 왔거나 `docs/PRD.md`, `PRD.md`, `**/PRD.md`가 있다 → **읽고 2.5단계로 건너뛴다.** 단, 아래 체크리스트 중 PRD에 빠진 항목이 있으면 그 항목만 짧게 인터뷰한다.
- 소스 코드가 이미 상당히 있다 → 이 스킬은 새 프로젝트용이라고 알리고, 계속할지 한 번 묻는다.
- `AGENTS.md`·`CLAUDE.md`가 이미 있다 → 3단계에서 덮어쓰지 말고 추가할 내용을 diff로 보여 준 뒤 확인받는다.
  `CLAUDE.md`에만 내용이 있으면 그 내용을 `AGENTS.md`로 옮기고 `CLAUDE.md`를 포인터로 바꾸자고 제안한다.
- `.claude/protected-paths`가 이미 있다 → 이전에 킥오프한 프로젝트다. 보호 훅 설치(3단계 마지막 명령)만 다시 실행해
  훅을 최신 버전으로 맞추고, 나머지 단계를 할지 묻는다.

## 1단계 — 인터뷰

### 규칙

1. **질문은 한 번에 하나.** 여러 질문을 묶지 않는다.
2. **질문마다 추천 답과 그 이유를 함께 제시한다.** 사용자는 "응"으로 넘어갈 수 있어야 한다.
3. **파일·웹을 읽어서 알 수 있는 건 묻지 않는다.** 직접 확인하고 "이렇게 확인했다"고 말한다.
4. **결정 트리를 따라간다.** 앞선 답이 뒤 질문을 바꾸는 경우(예: 팀 언어 → 스택), 앞의 것부터 확정한다.
5. 사용자가 "그만", "나중에"라고 하면 멈추고, 남은 항목은 PRD의 **열린 게이트**로 기록한다. 추측으로 채우지 않는다.

### 라운드 0 — 구성요소 확정

첫 질문 전에, 한 줄 아이디어에서 읽히는 **최상위 구성요소 목록**(예: 스캐너 / 변환 워커 / 관리자 UI)과
**이번 범위에서 뺄 것 후보**를 제시하고 확정받는다. 이후 인터뷰는 이 목록을 기준으로 한다.

### 명확도 체크리스트

아래 항목이 모두 ✅(답이 확정됨) 또는 ⏸(열린 게이트로 기록함)이 될 때까지 인터뷰한다.
**매 질문 앞에 현재 표를 짧게 보여 주고, 가장 비어 있는 항목을 겨냥한 질문이라고 밝힌다.**

| 항목 | 확정돼야 하는 것 |
|---|---|
| 문제·사용자 | 누가, 지금 어떤 불편을 겪는가. 역할이 여럿이면 역할별로 |
| 핵심 시나리오 | 구성요소별로 "사용자가 X를 하면 Y가 된다" 수준의 흐름 |
| 범위 밖 | 이번에 **하지 않을** 것과 그 이유 |
| 기술 제약 | 팀 숙련 언어, 기존 인프라, 배포 환경, 예산·규모 → 스택 결정 |
| 되돌릴 수 없는 것 | 절대 수정·삭제하면 안 되는 데이터·경로, 외부로 나가면 안 되는 정보 |
| 성공 기준 | **측정 가능한** 완료 조건 ("100% 등록" 대신 "미분류율 X% 이하"처럼) |
| 실패 처리 | 부분 실패·재시도·중단 시 데이터가 어떻게 남아야 하는가 |

"되돌릴 수 없는 것"은 사용자가 먼저 말하길 기다리지 않는다 — 2.5단계에서 Claude가 추론해 확인받는다.
인터뷰 중에 이미 드러났다면 그대로 기록해 둔다.

## 2단계 — PRD 작성

[prd-template.md](prd-template.md) 형식으로 `docs/PRD.md`를 쓴다.

- 인터뷰에서 나온 말만 쓴다. 인터뷰에 없던 결정을 새로 만들어 넣지 않는다.
- 파일 경로·코드 조각은 넣지 않는다 (금방 낡는다).
- 쓴 뒤 요약(구성요소, 불변 결정, 열린 게이트)을 보여 주고 확인받는다. 수정 요청이 있으면 반영한 뒤 다음 단계로 간다.

## 2.5단계 — 꼭 지킬 것 추론·확인

사용자는 "당연한" 제약을 말하지 않는다. PRD와 인터뷰 내용을 근거로 **Claude가 먼저 짐작해서** 제시하고 확인받는다.

### 추론 관점

PRD를 아래 관점으로 훑어 후보를 뽑는다. 각 후보는 **PRD의 어느 문장에서 짐작했는지** 근거를 갖고 있어야 한다. 근거 없는 일반론("보안이 중요합니다")은 후보가 아니다.

| 관점 | 신호 (PRD에서 찾을 것) | 예시 |
|---|---|---|
| 되돌릴 수 없는 데이터 | 원본, 마스터, 대체 불가, 운영 DB, 스토리지 스캔 | 원본 NAS의 파일 수정·삭제 금지 |
| 외부로 나가는 부수효과 | 발송, 결제, 배포, 외부 API 쓰기, 납품 | 실제 수신자에게 메일 발송 금지 |
| 민감 정보 | 개인정보, 라이선스·계약, 인증, 키 | 계약 데이터가 로그·픽스처에 들어가지 않게 |
| 비싼 자원 | 대량 변환, GPU, 유료 API, 전체 재처리 | 전체 자산 일괄 변환을 로컬에서 실행 금지 |
| 뒤집히기 쉬운 결정 | "~는 채택하지 않음", "과한 인프라", "범위 밖" | 큐 서버(Redis 등) 추가 금지 |
| 신뢰 경계 | 역할, 권한, 거부 시 403 | 권한 검사를 UI에서만 하지 않기 |

### 확인 방식

1. 후보를 **중요도 순으로 하나씩** 제시한다. 형식:
   > **짐작**: <지켜야 할 것>
   > **근거**: PRD "<인용 또는 요약>"
   > **강제 방법 제안**: <아래 표 중 하나 + 구체 내용>
   > 맞나요? (맞음 / 수정 / 해당 없음)
2. 강제 방법은 **가능한 한 결정적인 쪽을** 제안한다:

   | 강제 수준 | 수단 | 쓰는 경우 |
   |---|---|---|
   | 훅 (차단) | `.claude/protected-paths` | 특정 경로를 건드리면 안 되는 경우 — 실제 경로는 묻지 않는다. 사용자가 `.local`에 직접 적는다 (3단계) |
   | 규칙 | AGENTS.md 불변 규칙 | 경로로 표현할 수 없는 설계·범위 제약 |
   | 검증 | PRD 성공 기준·테스트 결정에 추가 | 동작으로 확인해야 하는 제약 (예: 403 반환) |

   훅이 있으면 좋겠지만 아직 teamcode에 해당 훅이 없는 제약(예: 특정 패키지 설치 금지)은 AGENTS.md 규칙으로 넣고,
   4단계 안내에 **"훅 후보"** 로 따로 적는다 — 플러그인 개선 입력이 된다.
3. "맞음"이면 확정 목록에 넣고, "해당 없음"이면 버린다. 사용자가 새로 말한 제약도 같은 형식으로 확정한다.
4. 후보는 5~7개 이내로 추린다. 너무 많으면 사용자가 읽지 않고 "응"만 누르게 된다.
5. 확정된 목록을 PRD의 "되돌릴 수 없는 것"과 해당 섹션에 반영한다.

## 3단계 — 하니스 생성

### AGENTS.md

30줄 안팎으로 짧게 쓴다. 매 세션 컨텍스트에 들어가므로 PRD 내용을 복제하지 않고 가리키기만 한다.
Claude Code 외의 도구(Cursor 등)도 읽으므로 Claude 전용 표현("훅이 막아 준다")에 기대지 않고, 규칙 자체를 적는다.

```markdown
# <프로젝트명>

<무엇을, 누구를 위해 — 2~3줄>
상세 요구사항: docs/PRD.md

## 불변 규칙 (PRD에서 확정됨 — 바꾸려면 PRD부터 고칠 것)
- <PRD 구현 결정 중, 구현 도중 "더 쉬운 길"로 뒤집히기 쉬운 것. 이유 한 줄 포함>
- <범위 밖 항목 중, 구현 중 슬쩍 추가되기 쉬운 것>

## 보호 대상 (어떤 도구로 작업하든 수정·삭제 금지)
- <되돌릴 수 없는 데이터> — 실제 경로는 각자 .claude/protected-paths.local에 (Claude Code·Cursor에서는 훅이 차단)

## 열린 게이트 (확정 전 해당 작업 착수 금지)
- <게이트> → 영향받는 작업

## 작업 방식
바꾸려면 먼저 docs/workflow-log.md에 변경과 이유를 남긴다.
```

불변 규칙은 **"모델이 구현 중에 어길 법한 것"만** 고른다. 너무 당연한 규칙("테스트를 작성한다")은 넣지 않는다.

`docs/workflow-log.md`가 없으면 [workflow-log.md](../shared/workflow-log.md)의 형식으로 빈 로그를 만든다. 이미 항목이 있으면 덮어쓰지 않는다.

### CLAUDE.md

```markdown
@AGENTS.md
```

Claude 전용 지시가 따로 생기면 이 아래에 덧붙인다. 공통 내용은 AGENTS.md에만 둔다.

### .claude/protected-paths (커밋) · .claude/protected-paths.local (커밋 안 함)

보호 경로는 두 파일로 나눈다. 훅은 두 파일을 합쳐 읽는다.

| 파일 | 커밋 | 내용 |
|---|---|---|
| `protected-paths` | ✅ | 2.5단계에서 "훅"으로 확정된 **보호 대상의 설명**(주석). 팀 전원에게 같은 경로가 확실할 때만 실제 경로 |
| `protected-paths.local` | ❌ | 각자 머신의 **실제 마운트 경로**. 사람마다 다를 수 있고, 저장소에 남기지 않는다 |

실제 경로는 **사용자에게 묻지 않는다.** 경로를 대화에 남기지 않도록, `.local`은 자리만 만들고 사용자가 직접 채우게 한다.

```
# .claude/protected-paths — 커밋
# 원본 마스터 파일 (PRD 스토리 20): 수정·삭제 금지
# 실제 경로는 각자 .claude/protected-paths.local에 적는다 (커밋 안 함)
```

```
# .claude/protected-paths.local — 커밋하지 않음. 이 머신의 실제 경로를 한 줄에 하나씩
# 원본 마스터 파일: 아래 주석을 실제 마운트 경로로 바꾼다
# /Volumes/NAS/masters
```

`.local`이 이미 있으면 건드리지 않는다 (사용자가 채운 값이다).
보호할 대상이 하나도 없으면 두 파일과 아래 훅을 만들지 않는다.

### 보호 훅 설치

`.claude/protected-paths`를 만들었다면, 이 스킬 디렉터리의 설치 스크립트를 **그대로 실행한다**.
`settings.json`을 손으로 고치지 않는다 — 스크립트가 기존 설정을 보존하며 병합하고, 여러 번 실행해도 결과가 같다.

```bash
python3 <이 스킬 디렉터리>/assets/install-guard.py <프로젝트 루트>
```

결과:
- `.claude/hooks/protect-paths.py` — 훅 스크립트 (버전이 다를 때만 교체)
- `.claude/settings.json` — `PreToolUse` 훅 등록 (`"$CLAUDE_PROJECT_DIR"/.claude/hooks/protect-paths.py`)
- `.gitignore` — `.claude/protected-paths.local`, `.claude/settings.local.json` 추가

이 훅은 두 보호 파일의 경로에 대한 Write/Edit와 `rm`·`mv`·`cp`·`sed -i`·리다이렉트 등을 차단한다.
Claude Code는 물론 Cursor도 `.claude/settings.json`의 훅을 실행한다 (Cursor 설정 → Agents → Third-Party Imports, 기본 켜짐).
커밋 대상: `protected-paths`, `hooks/protect-paths.py`, `settings.json`, `.gitignore`. `.local` 파일은 커밋하지 않는다고 안내한다.

## 4단계 — 다음 단계 안내

마지막에 다음을 짧게 안내한다.

0. **보호 상태** — `protected-paths`와 `protected-paths.local`을 합쳐 주석이 아닌 경로가 하나도 없으면 맨 위에 눈에 띄게 경고한다:
   > ⚠ 원본 보호 훅 비활성 — 등록된 경로가 없습니다. `.claude/protected-paths.local`에 이 머신의 실제 경로를 직접 적기 전까지 보호 대상은 문서 규칙으로만 지켜집니다. 팀원도 클론 후 각자 이 파일을 만들어야 합니다.

   훅은 Claude Code와 Cursor에서 동작한다. 그 밖의 도구(Codex 등)에서는 AGENTS.md 규칙으로만 지켜진다는 점도 함께 알린다.
1. 열린 게이트 목록과, 각 게이트를 닫으려면 누구에게 무엇을 확인해야 하는지
2. 작업 분해 — `/issues`로 PRD를 모듈 계약과 이슈로 나눈다. 열린 게이트에 막힌 작업은 착수 불가다
3. 이슈 하나가 준비되면 `/work`로 그 이슈만 구현한다. 스택이 열린 게이트로 남아 있으면 `/issues`가 자르기 전에 PRD 구현 결정을 먼저 묻는다. 뼈대를 만드는 일은 이 플러그인이 하지 않는다
4. **훅 후보**: 2.5단계에서 AGENTS.md 규칙으로만 넣은 제약 중, 훅으로 강제하면 좋을 것 (teamcode 개선 제안)
