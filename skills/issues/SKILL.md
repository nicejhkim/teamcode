# /issues — PRD를 이슈로

`docs/PRD.md`의 구성요소를 모듈 계약으로 옮기고, 그 계약으로 이슈를 자른다. 구현하지 않는다. 파일 경로와 코드는 적지 않는다.

한 이슈는 한 줄의 동작이다. 화면만, API만처럼 층을 나누지 않는다. 잘린 이슈는 `/work`가 하나씩 구현한다.

## 0단계 — 입력

사용자에게 묻기 전에 읽는다.

- 인자로 PRD 경로가 오면 그 파일을 읽는다. 없으면 `docs/PRD.md`, 그다음 루트 `PRD.md`를 읽는다. 없으면 멈추고 `/kickoff`로 PRD를 먼저 만들라고 알린다.
- `AGENTS.md`가 있으면 읽는다. 불변 규칙과 열린 게이트를 이슈에 반영한다.
- 기술 스택이 정해져 있지 않으면 이슈를 자르지 않는다. 구현 결정의 스택이 없거나, 비어 있거나, 미정으로 남아 있거나, 열린 게이트가 스택을 막고 있으면 해당한다. 한 가지만 묻는다. PRD에 이미 있는 기술 제약으로 추천이 서면 추천과 이유를 같이 말한다. 답을 듣기 전에 스택을 지어내지 않는다.

> 기술 스택이 PRD에 없습니다. 구현 결정에 스택과 이유를 적은 뒤에 자를까요?

  동의하고 스택이 정해지면, PRD 구현 결정의 **스택**을 고친다. 스택만 막던 열린 게이트는 PRD와 `AGENTS.md`에서 닫는다. 게이트를 닫는 일은 작업 방식의 변경이므로, 닫기 전에 [workflow-log.md](../shared/workflow-log.md)대로 `docs/workflow-log.md`에 변경과 이유를 남긴다. 고친 내용을 보여 준 뒤에만 다음으로 간다. 정하지 않겠다면 멈춘다.
- PRD 상태가 `draft`면 한 가지만 묻는다. 추천은 합의 후에 자르는 것이다.

> PRD가 아직 draft입니다. 이대로 자를까요?

## 1단계 — 계약과 이슈 초안

쓰기에 앞서 초안을 보여주고 확인받는다. PRD에 없는 스토리와 범위 밖 항목은 이슈로 만들지 않는다.

### 모듈 계약

PRD 구성요소마다 한 줄이다. 입력 → 출력만 적는다.

- **모듈** — 대응하는 PRD 구성요소. 입력 → 출력

### 세로로 자르기

각 이슈는 관련 모듈을 끝까지 한 번 통과하고, 그 자체로 확인 가능해야 한다. 얇게 여러 개로 나눈다.

이슈마다 다음을 정한다.

| 항목 | 내용 |
|---|---|
| 제목 | 짧게 |
| 종류 | 사람 결정이 필요하면 HITL, 아니면 AFK. AFK를 우선한다 |
| 선행 | 먼저 끝나야 하는 이슈. 없으면 없음 |
| 스토리 | 이 이슈가 덮는 PRD 사용자 스토리 |
| 수용 조건 | PRD 성공 기준과 그 스토리에서 가져온, 측정 가능한 조건 |

열린 게이트에 막힌 작업은 이슈로 남기되 상태를 **착수 불가**로 한다. 게이트, 확인할 대상, 막히는 이유를 적는다. 막히지 않은 이슈는 **착수 가능**이다.

초안 전체를 번호로 보여 주고, 한 번에 확인받는다.

- 잘게 나눈 정도가 맞는지
- 선행이 맞는지
- 착수 불가로 뺀 것이 맞는지

고칠 말이 있으면 고친 뒤 다시 보여 준다. 동의한 뒤에만 2단계로 간다.

## 2단계 — 기록

동의 전에는 파일을 만들지 않는다.

`docs/structure.md`에 모듈 계약, PRD의 범위 밖, 착수 불가 목록을 쓴다.

이슈는 선행이 앞에 오도록 `docs/issues/001-제목.md` 형식으로 쓴다.

```markdown
# 제목

상태: 착수 가능 | 착수 불가
종류: AFK | HITL
선행: 없음 | 001

## 무엇을

끝까지 한 줄로 동작하는 일. 층별 구현은 적지 않는다.

## 스토리

- PRD 스토리

## 수용 조건

- [ ] 측정 가능한 조건

## 막힌 이유

착수 불가일 때만. 게이트와 확인할 대상.
```

이슈 트래커 설명이 `docs/agents/issue-tracker.md`에 있으면 그 방식을 따른다. 없고 `gh`로 이 저장소에 이슈를 만들 수 있으면 한 가지만 묻는다. 추천은 `docs/issues/`다. `/work`가 그 파일을 바로 읽기 때문이다.

> 이슈를 GitHub에도 등록할까요?

등록한다면 파일과 같은 본문으로 만들고, 만든 번호를 파일에 적는다. 기존 이슈는 수정하거나 닫지 않는다.

## 3단계 — 안내

착수 가능한 이슈 중 선행이 없는 것부터 `/work`로 구현할 수 있다고 알린다. 착수 불가 이슈는 게이트가 닫히기 전에는 `/work`로 시작하지 말라고 알린다.
