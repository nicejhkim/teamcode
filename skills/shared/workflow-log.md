# 작업 방식 로그

진행 방식을 바꿀 때 따른다. `/kickoff`, `/issues`, `/issue`, `/work`가 해당 변경을 하기 전에 이 문서를 읽는다.

## 무엇을 남기는가

작업 방식은 다음이다.

- `AGENTS.md`의 불변 규칙, 열린 게이트, 보호 대상
- `/kickoff` → `/issues`(또는 `/issue`) → `/work`의 진행 순서와, 각 단계를 시작하거나 멈추는 조건

요구사항, 스토리, 스택, 성공 기준은 PRD에 고친다. 이슈 하나의 구현 내용과 버그 수정은 이 로그에 적지 않는다.

게이트를 열거나 닫아 착수할 수 있는 일이 바뀌면 로그에 남긴다. 그때 정한 스택이나 요구사항의 본문은 PRD에만 적는다.

## 언제 적는가

방식을 바꾸기 전에 변경과 이유를 사용자에게 확인받는다. 확인 전에는 고치지 않는다. 이유는 사용자가 말한 것만 적고, 지어내지 않는다.

확인되면 프로젝트의 `docs/workflow-log.md` 맨 위에 항목을 추가한 뒤 바꾼다. 파일이 없으면 아래 형식으로 만든다.

```markdown
# 작업 방식 로그

진행 방식을 바꾼 기록. 최신이 위다. 요구사항 변경은 PRD에 적는다.

## YYYY-MM-DD

- **변경**: 무엇을 어떻게 바꾸었는가
- **이유**: 왜 바꾸었는가
```

같은 날 변경이 여러 번이면 날짜 제목은 하나로 두고, 변경·이유 쌍을 그 아래에 추가한다.
